# 10/30论文可读性检测法

> 产线位置：第16期 · 正文工位 · 上游 [top-down-pyramid-writing] / 下游 [final-self-edit-checklist]

## R — 原文 (Reading)

> 教读者朋友一个很有效的测试方法，这个方法能够检查论文是否书写得清楚和明白，我们称之为"10/30检验法"。对于一般评审者来说，从开始阅读论文起计时，看他们能不能在10分钟内搞清楚你的研究问题是什么，研究工作的主要贡献是什么。在此基础之上，看他们能不能在30分钟内理解你的研究工作，包括方法和流程等(假设这是一个10页的会议论文)，并作出录用或是拒收的决定。
>
> — 凌晓峰、杨强，《学术研究：你的成功之道》第6章 6.3节

> 在被拒收的论文中，至少有一半的论文是因为书写问题而遭到拒收，而这当中包含很多以母语为英语的作者。
>
> — 同上，第5章 5.3节

---

## I — 方法论骨架 (Interpretation)

### 为什么10/30是合理的时间标准

评审者本身就是繁忙的研究者——他们同时担任教学、指导研究生、申请经费、组织会议等多重角色。一篇论文通常分配给2-5名评审者，每人不可能花几个小时逐页细读。10/30检测法模拟的正是真实评审场景下评审者所能投入的时间预算：10分钟扫读获取核心信息(问题+贡献)，30分钟足够通读全文并做出判断(甚至包括撰写评审意见)。如果在这两个时间窗口内评审者无法理解论文的核心内容，那么在真实的同行评审中，这篇论文几乎注定会被给出低分。

这与论文写得是否"高深"无关。评审者读不懂不等于你的工作高深——它只意味着你的表达有问题。

### 核心哲学

**"读懂论文是作者的责任，不是评审者的责任。"** 评审者不会也没义务查阅你的引用论文、翻看你过往的工作报告、或猜测你想要表达什么。他们只能从你递到他们手中的这份论文本身去寻找答案。如果你的论文无法让一个具备领域背景知识但未参与过你研究的同行在10/30分钟内读懂，那就是你作为作者的失职，不是评审者的失职。

### 10分钟测试考什么

考的是论文的**顶层叙事能力**——摘要和引言是否在最短时间内清晰传达了：
- 研究问题是什么？它为什么重要？
- 现有方法的不足是什么？
- 你提出的方法/思路是什么（高层次概括，不需要技术细节）？
- 你的主要贡献/发现是什么？

如果读者读到这里就已经"迷失"，说明论文缺乏一个清晰的、自上而下的叙事框架。

### 30分钟测试考什么

考的是论文的**中层论证清晰度**——在理解研究问题和贡献之后，读者能否：
- 理解你的方法流程和关键技术选择
- 理解实验设计及其合理性
- 看懂关键结果和对比分析
- 形成对论文的整体判断（录用/拒收及原因）

30分钟后如果读者还停留在"大概明白但说不清楚"的状态，说明论文在逻辑结构和论证链条上存在漏洞。

## A1 — 书中的应用 (Past Application)

### 案例：超过一半拒稿源于书写问题

- **问题**: 两位作者在多年担任程序委员会主席和评审者的过程中发现，被拒收的论文中至少有50%是因为书写问题——不是语言问题，而是逻辑混乱、结构不清、论点模糊。令人意外的是，这其中包括大量母语为英语的作者。也就是说，"英文不好"是一个被严重高估的借口，真正的病灶是作者没有做到"让论文容易被读懂"。
- **方法论的使用**: 10/30检测法是作者针对上述问题提出的解决方案。它不是教你如何写得"更优美"，而是提供一个可量化的检验标准——如果你找的测试者通不过10/30，无论你觉得自己的论文写得有多好，都意味着它存在结构性缺陷。
- **结论**: 在评审过程中，前三个打分维度(新颖性、影响力、技术方法)都会因论文写得不够清楚而受到连带影响——评审者看不懂就会质疑。书写问题排第四，但它是前三项的"放大器"。10/30测试正是为了在投稿前消除这个放大器效应。
- **结果**: 作者强调，只要采纳10/30检测法并愿意反复修改直到通过，论文的书写问题将不再成为被拒收的理由。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. **投稿前质量自检** — 用户已经完成论文初稿，想确认论文的可读性是否达到投稿标准，但又不知道如何客观衡量。
2. **被拒稿后反思** — 用户收到拒稿通知，评审意见中提到"难以理解""逻辑不清""贡献不明确"等，用户想知道问题出在哪里以及如何修复。
3. **写作过程中的中期检查** — 用户已经完成某个章节或模块(如引言+方法)，想检验当前版本是否足够清晰，是否能被同行理解。

### 语言信号 (用户的话里出现这些就应激活)

- "论文写完了但不确定好不好"
- "投稿前怎么检查论文质量"
- "怎么知道论文够不够清楚"
- "帮我看下这篇论文能不能投"
- "论文写完了但总觉得哪里不对"
- "投之前怎么让同事帮忙看"
- "被拒了，审稿人说读不懂"
- "怎么自查论文的可读性"

### 与相邻 skill 的区分

- 与 `top-down-pyramid-writing`(金字塔写作法) 的区别: 金字塔写作法教你怎么**写出**结构清晰的论文(写什么内容、按什么顺序、每层怎么说)，是写作阶段的工具。10/30检测法教你怎么**检验**已经写出来的论文是否真的足够清晰，是写作完成后、投稿前的验证工具。金字塔写作法在前，10/30检测法在后。如果10/30通不过，应该回到金字塔写作法去修改。
- 与 `grays-criteria-problem-evaluation`(格雷准则选题筛选) 的区别: 格雷准则帮你在选题阶段判断"这个研究问题值不值得做"。10/30帮你在写作完成后判断"这篇论文写得够不够清楚"。一个是选题阶段的筛子，一个是投稿前的筛子。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行:

1. **确认论文状态**
   - 验证用户是否已有完整初稿(至少具备摘要、引言、方法、实验、结论的完整结构)。
   - 完成标准: 确认论文具备上述五个核心模块。
   - 判停条件: 若论文尚未完成初稿，告知用户10/30检测需要完整论文才能执行有效测试，建议先完成写作(可激活金字塔写作法skill)。

2. **准备测试环境**
   - 解释10/30检测法的原理和目的。
   - 引导用户准备测试材料: 将论文发给2-3名同事。
   - **重要**: 测试者中最好有1-2人**不属于你的细分研究领域**但具有该领域的基础背景知识——这样最能模拟真实评审者的知识水平。全找同课题组的同学反而测不出问题(他们对你的工作太熟悉了)。
   - 完成标准: 用户确认已选定测试者并发送论文。

3. **执行10分钟测试**
   - 告知测试者: 只阅读论文的**题目、摘要和引言**(不读方法、实验部分)。设定计时器为10分钟。
   - 10分钟后，向测试者提问:
     - "这篇论文要解决的研究问题是什么？"
     - "为什么这个问题重要？"
     - "作者提出的方法是什么(高层次概述即可)？"
     - "这篇论文的主要贡献是什么？"
   - 记录测试者的回答。如果任何一位无法清晰回答上述问题，标记为"10分钟测试未通过"。
   - 完成标准: 所有测试者对以上问题的回答都准确且一致。

4. **执行30分钟测试**
   - 测试者继续阅读论文其余部分(方法、实验、相关工作和结论)。设定计时器为30分钟。
   - 30分钟后，向测试者提问:
     - "这篇论文用的大致方法/技术路线是什么？"
     - "实验设计是否合理？关键结果是什么？"
     - "如果你来做评审，你会建议录用还是拒收？理由是什么？"
   - 注意: 测试者的回答不必完全赞同论文的观点，但必须能**准确复述**论文的方法和论证逻辑。如果测试者说"方法部分没看懂"或"不知道为什么作者要做某个实验"，即使他倾向于录用，测试也不算通过。
   - 完成标准: 所有测试者能准确理解研究方法和论证逻辑，并给出有理由的判断。

5. **汇总结果与行动建议**
   - 汇总: 几位测试者通过了10分钟测试？几位通过了30分钟测试？
   - 如果所有测试者均通过 → 论文可读性达标，可以投稿。
   - 如果有任何一位未通过 → 论文需要修改。收集测试者的困惑点，定位论文中导致可读性问题的具体段落，回到金字塔写作法重新梳理逻辑和结构。修改后再做新一轮10/30测试。
   - 完成标准: 生成一份检测报告，包含测试结果、未通过的原因归类、建议修改的具体章节。
   - **关键原则**: 通不过就是通不过。不要自我安慰"这个人不是我的领域所以看不懂"——如果测试者具备该领域基础背景知识，看不懂就是论文的问题。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- **论文尚未完成完整初稿** — 10/30检测需要完整的论文结构(至少包含摘要、引言、方法、实验、结论)。初稿未完成时，应先使用金字塔写作法完成写作。
- **评审者已非常熟悉你的工作** — 如果你的测试者是你的导师、同课题组成员、或每周参加你的研究讨论会的人，他们已经在日常交流中形成了对你工作的深度认知。让他们做10/30测试无法模拟真实评审者的知识起点，测试结果没有参考价值。
- **测试者完全不理解你的领域** — 找一位完全不懂机器学习的人去测试一篇机器学习论文，他当然通不过10/30测试，但这不说明论文有问题。测试者需要具备该领域的基础背景知识(如同"一般评审者"的水平)，否则测试无意义。作者原文强调应找"在相似或者相同领域做研究的同事"。

### 此方法的重要限制

- **10/30是通过性测试，不是充分性测试** — 通过10/30测试只代表论文在可读性维度上合格，不代表论文一定被录用。论文的最终录用还取决于研究本身的创新性、影响力、技术正确性等维度。10/30只是帮你消除"因为写不清楚而被拒"这一项风险。
- **测试结果受测试者主观因素影响** — 不同测试者的背景、阅读习惯、耐心程度都会影响测试结果。建议至少找2-3人做测试，取多数意见。如果结果出现分歧(一人通过、一人不通过)，应以不通过者的反馈为重点修改依据——因为真实评审中你无法选择评审者。
- **10/30不解决语言问题，它解决结构问题** — 正如作者所强调的，书写问题的主要根源是逻辑和结构，不是英语水平。10/30检测如果通不过，不应该把原因归为"我英文不好"，而应该去找金字塔式逻辑论证的问题。

### 容易混淆的邻近方法论

- **非"同事随便看看"** — 有人会把论文发给同事说"帮我看看有什么问题"，这种没有时间限制和具体目标的"看看"不是10/30检测。10/30检测必须严格计时，且有明确的检验问题。
- **非"导师把关"** — 导师的深度审阅和逐页修改是另一个独立的工作流(PI循序渐进式指导法)。10/30检测是模拟真实评审的快速判断，不是替代导师的深度指导。
- **10/30与自问自答式自查不同** — 作者在6.2节中也讨论了"角色转换自查法"(作者变身为读者自问自答)，但明确指出自查最大的问题是"你太了解自己的研究，无法模拟真正无知读者的视角"。10/30检测必须由外部测试者执行，不能由作者自己替代。

### 作者的盲点 / 时代局限

- **2012年出版，未考虑AI辅助工具** — 当时没有ChatGPT、Claude等LLM可以作为辅助"模拟读者"来检验论文的可读性。在今天，可以先让LLM阅读论文并让它复述研究问题和贡献，作为一种初步的、低成本的替代方案(但不能完全替代真人测试)。
- **假设了较为充裕的同行网络** — 找2-3个合格的同行做测试这项前置条件，对某些孤立的博士生(例如导师放养、课题组规模小、领域极度冷门)可能非常困难。书中未讨论这种情况的替代方案。
- **"10页会议论文"的标准以CS领域为默认** — 不同学科和期刊的论文长度差异巨大。对于30页以上的长论文，30分钟的基准可能需要调整(但仍应保持"评审者不会花超过几小时"这一原则)。
