# 博士论文蓝图制定法

## R — 原文 (Reading)

> "在博士二年级快要结束时，做研究的三项主要任务应该完成了一次或者两次了，现在你应该开始为博士论文制定蓝图了。粗略地看，这个蓝图更像未来博士论文的目录。"
>
> "要切记一点，蓝图不是宪法，你不能被它所束缚……你最终完成的博士论文与原先制定的蓝图会有50%～80%的吻合度。"
>
> "博士论文应该具有一致性，专注于一项研究课题。"
>
> — 凌晓峰, 杨强, 第3章3.7节 / 第2章2.1节

---

## I — 方法论骨架 (Interpretation)

博士论文蓝图制定法解决的核心问题是: **你已有了几个研究想法和一些初步成果，但不知道如何把它们组织成一篇有说服力的博士论文。**

这个方法的逻辑是——

**为什么是二年级结束?** 太早了不行: 博士第一年你还在上课、读论文、探索方向，连自己能做什么课题都没搞清楚，这时候就试图规划未来3年的论文结构，跟用占星术规划职业生涯差不多。太晚了也不行: 如果到了三年级甚至四年级才开始想"我的博士论文到底要写什么"，你会发现手头的东西根本串不起来——这篇论文和那篇论文讲的理论上是两个不同的故事，把它们硬拼在一起就像把《哈姆雷特》和《哈利波特》剪辑成一部电影。

**蓝图的本质**是一份"目录级的论文契约"。你对着这份目录向自己(和导师、答辩委员会)承诺: 我的博士论文由一个中心论点和若干个(5-10个)子问题组成，每个子问题对应一章或一组实验，它们逻辑一致、目标统一，全部服务于那一个中心论点。

**蓝图不是宪法**——这是整个方法论中最重要的一句话。制定蓝图不是为了限制你，而是为了给你一张地图: 你知道自己在哪、要去哪、还剩多少路。途中发现新大陆(标注`new`)、放弃无法攻克的山峰(标注`unfinished`)，都是正常操作。最终成品和原始蓝图50%～80%吻合，既说明你在路上学到了新东西，也说明你没有在迷宫里彻底迷路。

**两种组织路线**: 自上而下——先确定中心论点，再用棋盘法自上而下分解为子问题；自下而上——先发表了几篇论文，再回头从这些论文中归纳出一个统一主题。两种路线可混合使用，核心不变: 最终出品的博士论文必须围绕一个中心论点展开。

**一致性是第一铁律**: 早期探索过但最终不在中心论点辐射范围内的课题(比如A1的协同训练研究)，即使已经发了论文，也不该出现在博士论文中。`n`篇硕士论文 ≠ 1篇博士论文。

## A1 — 书中的应用 (Past Application)

### 案例: 博士生A1的博士论文蓝图 (图3.4)

- **问题**: A1早期研究方向是协同训练(co-training)，发了顶级会议论文。但几次头脑风暴后，他发现协同训练"并不是件容易的博士论文课题"——难以展开成有足够深度的系统性研究。他把方向转向了"基于数据获取的代价敏感学习"(cost-sensitive learning with data acquisition)。

- **方法论的使用**: 导师和A1一起制定蓝图。中心论点确定为 **Cost-Sensitive Learning with Data Acquisition**。围绕这个中心论点分解出子问题和对应发表的论文:
  - **特征获取的代价敏感学习** → 串行策略 `[ECML 2005]` → 简单批处理策略 `[AAAI 2006]` → 顺序批处理策略 `[TKDE 2007]` → 考虑延迟成本 `[new; ECML 2007]`
  - **实例获取的代价敏感学习** `[new]` → 部分与完全实例获取 `[KDD 2008]`
  - **获取策略的理论保证** `[unfinished]`
  - **真实环境部署** `[unfinished]`
  
  每个子问题标有状态: 已发表(会议期刊+年份)、`new`(后加入)、`unfinished`(未完成)。

- **结论**: 整个蓝图围绕一个中心论点展开，层次分明。最终博士论文完全没有包含早期协同训练的工作——因为它不服务于"代价敏感学习与数据获取"这个中心论点。

- **结果**: A1用4年完成博士学位，发表了10多篇顶级期刊和会议论文，成为该领域的开山鼻祖，"他的想法已经像手电光一样'照亮'了这一研究领域"。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **博士生二年级即将结束**，已完成1-2次探索→研究→发表的三步迭代，手头有一些研究成果但不知道如何整合成一篇博士论文
2. **博士生三年级了还没有确定论文框架**，导师在催开题，但学生大脑里还是一堆散装的研究碎片
3. **要开题答辩了**，需要向答辩委员会展示一个逻辑自洽、结构完整的论文计划，而不是几篇互不相关的论文列表
4. **正在写博士论文**，发现手头的论文和实验结果拼不到一起，需要回头确定中心论点、重新组织叙事
5. **准备博士答辩的演讲叙事**，需要把几年的研究浓缩成一条逻辑链——"我研究了什么→为什么重要→怎么解决的→证明了什么"

### 语言信号 (用户的话里出现这些就应激活)

- "博士论文怎么写"
- "博士论文结构怎么安排"
- "博士论文框架怎么搭"
- "要开题了怎么准备"
- "毕业论文开题报告"
- "博士三年级了还没确定论文框架"
- "博士论文答辩时怎么组织叙事"
- "怎么把发表的几篇论文串成一篇博士论文"
- "dissertation怎么写"
- "PhD thesis structure"
- "课题游击战" — 用户意识到自己涉猎太广需要聚焦
- "我做了好几个方向的东西不知道怎么整合"

### 与相邻 skill 的区分

- 与 `top-down-pyramid-writing` (v04) 的区别: v04 教你写一篇**单篇**会议/期刊论文——标题→摘要→引言→正文→结论的金字塔结构。本skill教你的是**整篇博士论文**的宏观规划——5-10个子问题如何围绕一个中心论点组织、已发表论文如何成为博士论文的各个章节。前者是"怎么写好一篇文章"，后者是"怎么规划整个博士生涯的最终作品"。
- 与 `matrix-method` (v01 棋盘法) 的关系: 棋盘法在本skill中作为**分解工具**出现——用棋盘法的横轴(方法)×纵轴(问题)框架，将中心论点分解为子问题和子方法。
- 与 `gray-criteria` (v02 格雷准则) 的关系: 格雷准则用于筛选和验证每个子问题是否"配得上"进入博士论文蓝图。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤指导用户:

1. **确定中心论点**
   - 回顾用户已完成的研究(已发表的论文、已有的实验结果、已探索的课题)
   - 从中识别出一个能够统摄大部分工作的核心研究问题
   - 用"电梯描述法"检验: 能不能用一句非专业语言，在30秒内向一个外行讲清楚你的博士论文研究什么？
   - 如果不能 → 中心论点还不清晰，需要继续提炼
   - 完成标准: 用户能自信地说出"我的博士论文研究的是X问题"，且X能涵盖其大部分已有工作
   - 从用户早期探索过但不相关的课题中排除(这些不纳入博士论文)——此为一致性原则

2. **用棋盘法将中心论点分解为子问题(5-10个)**
   - 以研究问题的子方向为纵轴、以研究方法或技术维度为横轴，构建棋盘
   - 在棋盘上定位用户已完成的工作(已发表的论文落在哪些格子)
   - 识别空格子: 哪些子问题还没有被研究过？哪些方法还没有被尝试过？
   - 从空格子中筛选出最有价值的5-10个子问题纳入蓝图
   - 完成标准: 每个子问题都能清晰地解释"它为什么是中心论点的一个合理组成部分"

3. **为每个子问题标注状态**
   - 已完成并发表: 标注会议/期刊简称和年份，如 `[AAAI 2006]`
   - 正在进行中(有初步结果): 标注 `[ongoing]`
   - 计划中但尚未开始: 标注 `[planned]`
   - 后来新加入的: 标注 `[new]`
   - 最终可能无法完成的: 标注 `[unfinished]` —— 允许放弃
   - 完成标准: 蓝图上每个子问题的状态一目了然

4. **绘制目录级蓝图**
   - 论文标题 = 中心论点的浓缩表述
   - 第一章: 引言(研究动机、中心论点、贡献列表)
   - 第二章: 相关工作
   - 第三章至第N章: 每个子问题展开为独立章节，每章对应一个或多个已发表论文
   - 最后章: 结论与未来工作
   - 输出格式: 树状目录，每个章节标注对应的子问题和论文状态
   - 完成标准: 用户看到这份目录能立刻说出"这就是我接下来要写的博士论文"

5. **制定更新节奏**
   - 每3-6个月重新审视蓝图
   - 已完成的子问题 → 更新状态
   - 新发现的方向 → 评估是否纳入蓝图，标注 `[new]`
   - 确定无法完成的 → 标注 `[unfinished]` 或删除
   - 保持最终成品与蓝图50%-80%的吻合区间
   - 完成标准: 用户建立了定期审视和更新蓝图的习惯，而非制定一次就束之高阁

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **硕士论文**: 硕士论文通常只有一个研究问题，不涉及多子问题的整合规划。硕士不需要(也不应该)制定一个"围绕中心论点分解5-10个子问题"的蓝图——那是过度规划。
- **已有明确固定框架模板的学科**: 某些工程学科或国家的博士论文有固定的格式要求(如几个固定实验、固定章节结构)，蓝图法在这些情况下空间有限。
- **导师已经定死了课题且无任何调整空间**: 蓝图法的前提是博士生有自由选择子问题、调整研究方向的余地。如果课题、方法、章节都被导师指定得明明白白，用户需要的不是"蓝图制定法"而是"如何高效执行既定计划"。

### 作者在书中警告的失败模式

- **"课题游击战"** (第2章): 涉足太多不同课题，每个都是浅尝辄止，最终无法围绕一个中心论点制定蓝图——因为根本没有中心。
- **"学术三脚猫"** (第2章): 在每个课题上都发表了一些成果，但都不足以成为领域风向标。博士论文变成"不同课题的大杂烩"，缺乏一致性，可能无法通过答辩。
- **蓝图变成宪法** (第3章): 过于死板地执行蓝图，不敢添加新发现的问题、不敢放弃做不出来的子问题。最终论文要么错过了重要方向，要么留下了凑数的章节。

### 作者的盲点 / 时代局限

- **2012年出版**，深度学习革命(ImageNet 2012)和大模型时代(GPT系列)尚未爆发，现代AI领域的博士生面临的科研节奏和竞争压力远超书中描述。蓝图每3-6个月更新可能在快节奏领域已不够，建议AI/ML领域的博士生每2-3个月审视一次。
- **两位作者均任职于北美/香港顶尖CS院校**，案例集中在计算机科学。对于人文社科、理论物理等专著式博士论文为主流的学科，蓝图法中的"多篇已发表论文集合体"模式可能不完全适用，需要调整为核心章节×子论点的对应关系。
- **假设了导师支持且学生有课题选择自由**。现实中大量博士生的课题由导师的基金项目决定，学生自主调整空间有限。这种情况下面向用户的角色从"自主蓝图设计师"转变为"在给定框架内与导师协商子问题分布"。

### 容易混淆的邻近方法论

- **开题报告 (proposal)** ≠ 蓝图。开题报告是一次性的行政文件，通常只包含初步计划。蓝图是贯穿博士后半程的动态工具，持续更新、灵活调整。
- **论文大纲 (outline)** ≠ 蓝图。大纲是写作阶段的章节罗列，蓝图是包含研究问题状态、论文发表状态、子问题之间逻辑关系的战略地图。
