# 回复审稿人

> 产线位置：第18期 · 投稿返修工位 · 上游 [final-self-edit-checklist] / 下游 [无（产线终点）]

## R — 原文

> 部分会议在作出最终判决前，会把评审意见告诉作者，允许作者在规定时间内（通常几天）给予反馈，用以纠正评审者可能出现的误解或对评审者提出的问题进行答复。要尽最大努力提供简洁而清晰的回复；如果遇到评审者对论文有不正确或不准确的理解，可以坚决地给予纠正。
>
> — 凌晓峰、杨强，第5章 5.8节

> 他们普遍认为读懂论文是评审者的责任……"审稿人这么粗心。他们指出的……，我已经明确地写在了第5页右列第23行！"
>
> — 同上，第6章 6.2节（反面引述）

---

## I — 方法论骨架

回复审稿人 = 一套心态 + 两条路径。

### 心态三原则（比回复技巧更重要）

1. **读懂论文是作者的责任，不是审稿人的**。评审者每天要审十余篇论文，每篇只有几十分钟。如果你不能在10分钟内说清核心贡献，那是你失败了。被拒后第一反应是"审稿人根本不懂"，就是受害者的自我服务偏差——把成功归因于自己、失败归因于外部。
2. **不猜忌、不对抗**。"审稿人是竞争对手所以拒我"是没有证据的阴谋论——顶级期刊和会议采用双盲评审和利益冲突回避机制。把精力花在猜身份上，就永远不会去面对论文真正的问题。
3. **拒绝不等于失败，评审意见是免费咨询**。论文被接收说明课题可行；被拒收也能从评审意见中获得提升方向。审稿人花了几十分钟免费帮你挑毛病——这是你在这个领域能获得的最廉价的高质量反馈。

### 两条路径

- **期刊修回信（Response Letter）**：审稿意见 → 逐条回复 → 修改稿标注。可以多轮往返，修改后重新提交。
- **会议 rebuttal**：一锤子买卖。会议与期刊不同，不能修改后重新提交同一次会议；rebuttal 是争取录用的最后防线，通常只有几天时间、篇幅极短，要"简洁而清晰"。

## A1 — 书中的应用

### 案例 1：rebuttal 的"一锤子买卖"性质

会议评审流程中，部分会议在最终判决前给作者一次回复机会。作者强调：这是流程内的正式环节（不是事后申诉），也是唯一一次纠正审稿人误解的机会。正确姿势是"尊重但坚定"——不情绪化吵架，但遇到审稿人对论文的误解（如"方法X和已有方法Y相同"而实际上有本质区别），要坚决澄清。

### 案例 2：被拒后的正确姿势——从评审意见中提升

作者建议博士生第一年尾声到第二年初完成一次完整投稿迭代：论文被接收说明课题可行；**被拒收也能从评审意见中获得提升方向**。评审意见是校准自己写作和研究的免费诊断——被拒不是终点，是信息。

### 案例 3：三类失败心态（反面教材）

- "我的结果这么好，评审者不可能看不出来"——把评判权推给评审者，而不是明确论证"为什么我的工作重要"。论文评审不是品鉴会，是论证法庭：你没有义务谦虚，你有义务说服。
- "已经很完美了，不用再改"——宜家效应（对自己创造的东西赋予过高价值）+ 达克效应。收到修改建议第一反应是防御的，说明认知天花板到了。
- "评审者是我的竞争对手或其朋友"——没有证据的利益冲突指控极不负责任，且阻止作者面对真正问题。

## A2 — 触发场景 ★

### 用户会在什么情境下需要这个 skill？

1. 收到期刊"大修/小修"意见，看着逐条评论不知道回复信怎么写
2. 收到会议 rebuttal 通知，只有几天时间，不知道格式和分寸
3. 被拒稿后愤怒/沮丧，想写邮件质疑编辑或审稿人
4. 审稿意见里有明显误解（审稿人说"你没做X"但论文里做了），不知道该怎么"顶回去"才得体
5. 导师说"你自己回审稿人"，第一次独立面对评审
6. 不确定什么情况可以申诉、怎么申诉

### 语言信号

- "审稿意见怎么回复""修回信怎么写"
- "被拒了怎么办""还能申诉吗"
- "rebuttal怎么写""rebuttal格式是什么"
- "大修和小修有什么区别"
- "审稿人说我的贡献不够，我该怎么回应"
- "能不能跟审稿人争论"
- "审稿人根本没看懂我的论文"

### 与相邻 skill 的区分

- 与 `ten-thirty-readability-test` 的区别：10/30 检测是**投稿前**用外部测试者模拟评审；本 skill 是**投稿后**面对真实评审意见的回应。10/30 通过率高的论文，回复审稿人时"被误解"的概率低。
- 与 `final-self-edit-checklist` 的区别：终稿自检是交稿前对自己文稿的扫描；本 skill 是交稿后对他人意见的回应。心态同源——"读者永远是对的"延伸到"审稿人是你的第一读者"，即使要坚决纠正误解，也要先假设审稿人是对的、检查自己是否写清楚了。

## E — 可执行步骤

当 skill 被激活后，agent 应按以下步骤执行：

### 1. 心态校准

- 检查用户的初始反应：如果是"审稿人不懂/不专业/有利益冲突"，先引导归因转向——"假设审稿人的意见有道理，我们的论文哪里造成了这个印象？"
- 提醒：审稿意见是免费的高质量反馈；猜身份没有证据也没有收益
- 完成标准：用户能平静地逐条面对意见，不再处于防御状态

### 2. 分类审稿意见

把每条意见归入五类，不同类型的回应策略不同：

| 类型 | 典型表述 | 回应策略 |
|---|---|---|
| 误解类 | "作者没有做X"（其实做了） | 礼貌指出版本中的具体位置，同时在修改稿中把X写得更显眼 |
| 建议类 | "建议补充Y实验" | 能做到的做；做不到的给出替代方案或解释成本 |
| 质疑类 | "Z结论证据不足" | 补数据/补论证，或适当收窄结论表述 |
| 笔误/格式类 | 直接改正并致谢 |
| 立场分歧类 | "方法A不如方法B"（根本分歧） | 尊重但坚定地论证；实在无法调和时礼貌说明分歧点，交编辑裁量 |

### 3. 期刊修回信：结构模板

```
致尊敬的编辑与审稿人：

感谢您们的时间和宝贵意见。这些意见帮助我们显著改进了论文。
以下是逐条回复：

审稿人1
意见1.1 [原意见引述或概括]
回复：……（先总结做了什么，再给具体修改，标注位置）
修改位置：第X页第Y段（修改稿中用红色标注）

意见1.2 ……

审稿人2
……

主要修改摘要：
1. 新增……（第X节）
2. 补充实验……（表Y）
3. ……
```

关键规则：
- **逐条回复，一条不漏**——宁可编号重复也不合并跳过；每条先复述或概括原意见，证明你认真读了
- **先致谢后回应**——即使意见是误解，也先感谢审稿人花时间阅读
- **修改位置必须可追溯**——页码/行号/颜色标注三件套；给"修改前→修改后"对照更好
- **语气：礼貌、具体、不谄媚**——"We agree with the reviewer that..."之后可以跟"However, we respectfully disagree because..."
- **审稿人理解错误时**：不要写"你错了"，写"我们意识到原文的表述可能造成了误解，已在第X节改写为……"——把责任揽到自己表述上，同时坚决澄清事实

### 4. 会议 rebuttal：一锤子买卖

- **时间极短、篇幅极小**：只回对录用判决有影响的关键点，不逐字回应
- **简洁而清晰**：每条回复1-3句话，直击要点
- **可坚决纠正误解**：审稿人把方法弄错、把相关工作搞混时，明确指出"我们的方法与Y有三点本质区别：……"
- **不能做的事**：不能补充新的实验结果（流程不允许）、不能修改论文本体、不能情绪化
- **认清性质**：rebuttal 是流程内环节不是申诉；过了就过了，没有第二次机会

### 5. 修改稿同步更新

- 修改稿与回复信必须一一对应：回复信里说改了什么，修改稿里就真的改了
- 改完后回到 `ten-thirty-readability-test` 做一轮快速自测（新加的内容不要破坏可读性），再用 `final-self-edit-checklist` 扫描一遍
- 完成标准：编辑和审稿人可以仅凭回复信 + 标注版修改稿，不翻原文就完成复审

### 6. 申诉边界（谨慎）

- 申诉（appeal）只适用于：编辑处理流程错误、审稿存在明确利益冲突证据、意见中存在可证明的事实性错误且编辑拒绝再审
- 申诉对象是编辑，不是审稿人；措辞冷静、陈述事实
- 大多数"审稿人不懂"的情况不是申诉理由——先检查是不是自己没写清楚

## B — 边界 ★

### 不要在以下情况使用此 skill

- 论文还在写作或自查阶段——先跑 `final-self-edit-checklist` 和 `ten-thirty-readability-test`，能显著减少"被误解"的概率
- 与审稿人进行与研究无关的争论或人身攻击——学术争论只围绕证据和论证
- 用 AI 生成回复信后不加人工审核——AI 可以起草框架和措辞，但语气分寸、事实核对（修改位置、页码）必须人工把控；AI 容易写出过度谄媚或过度辩护的文字
- 把"坚决纠正误解"做成"吵架"——纠正的是事实，不是胜负

### 作者在书中警告的失败模式

- **猜忌评审者有利益冲突**（ce15）：用阴谋论解释拒稿，阻止作者面对真正问题
- **"读懂我是你的责任"**（ce09）：把被拒归因于评审者水平，而不是自己论文不够清晰
- **"已经很完美了"**（ce14）：拒绝继续修改，认知天花板之上停止了成长
- **论文过度谦虚**（ce08）：不在论文中论证自己的贡献，指望评审者自己发现——但在回复信中要反过来，明确、有力、有证据地论证贡献
- **降低档次回避书写问题**（书中投递策略）：论文因书写问题被拒后，不修书写而是改投低档次期刊——"非常好"的研究成果应发表到"非常好"的期刊

### 作者的盲点 / 时代局限

- **2012年成书，未涉及AI辅助回复**：LLM 可以起草回复信、分类审稿意见、检查回复信与修改稿的一致性，但最终语气和事实必须人工把关
- **会议 rebuttal 的流程因领域而异**：CS 顶会的 rebuttal 是主流，但许多学科没有这一环节；使用前先确认目标会议的流程
- **中文期刊生态不同**：国内期刊的修改流程、与外审专家的沟通方式（常通过编辑转达）与英文期刊不同；心态原则通用，操作细节需适配

### 容易混淆的邻近方法论

- **rebuttal ≠ 申诉**：rebuttal 是会议流程内的正式环节；申诉是流程外的事后救济，对象是编辑
- **"读者永远是对的" ≠ 无脑顺从审稿人**：先假设审稿人是对的去检查自己的表述；检查完发现是事实性误解，就坚决而礼貌地纠正——两者不矛盾，顺序很重要
